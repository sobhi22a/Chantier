### Suggestions
- Mobile : détecter un recul de l'horloge (`maintenant < dernier contact` ⇒ session expirée, `auth_repository_impl.dart:66-70` accepte aujourd'hui une durée négative) ; verrouillage par code du téléphone ou de l'application avant les données personnelles ; `FLAG_SECURE` sur les écrans de montants ; épinglage de certificat à étudier pour les réseaux mobiles locaux.
- Backend : liste de mots de passe interdits et longueur 10 pour les comptes Admin (politique actuelle : 8 caractères dont un chiffre) ; retirer `Bootstrap:AdminPassword` de la configuration après le premier démarrage ; journaliser les échecs de connexion avec l'identifiant haché et l'IP pour pouvoir détecter les attaques ; activer `READ_COMMITTED_SNAPSHOT` sur la base : le « toucher » d'affectation verrouille la ligne du chantier et fait attendre toutes les lectures (contrôle d'affectation, pull) pendant sa transaction ; limiter les opérations d'un lot de push à un contrôle d'affectation par chantier plutôt que par opération.
- Web : fixer la CSP et les en-têtes de sécurité du serveur qui hébergera le SPA (le `index.html` n'en porte aucune) ; sans effet sur le socle, le stockage navigateur ne contient que la langue (`chantier.lang`).

## Mesures
Méthode : binaire Release copié dans le dossier temporaire de session, lancé en Development sur le port 8199 (base SQL Server de développement, jeu de démonstration « École UV18 », 2 chantiers et 30 zones), `node` + `fetch` en local, journal EF `Database.Command` activé pour compter les requêtes. Réseau local : les temps sont des bornes basses, ils ne représentent pas un téléphone en 3G.

## Points positifs
- Isolation par chantier cohérente et réellement identique pour inexistant/non affecté, filtre de ressource avant la liaison du corps, test d'architecture sur `{siteId}`.
- Connexion : réponse unique, blocage qui ne révèle pas l'existence d'un compte, hachage factice pour les inconnus ; refresh haché, rotatif, atomique ; JWT strict (algorithme, émetteur, audience) ; `ACCES_RETIRE` à ≤ 60 s sur jeton et cookie.
