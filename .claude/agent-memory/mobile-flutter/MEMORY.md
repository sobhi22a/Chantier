## Conventions
- Code Dart en `snake_case`, imports `package:chantier_mobile/...` (lint `always_use_package_imports`), commentaires sans accents, textes UI uniquement via ARB (`lib/l10n/app_fr.arb` gabarit + `app_ar.arb`).
- Erreurs serveur traduites par `code` (`core/l10n/error_messages.dart`) ; le test compare au catalogue `docs/api/codes-erreur.md` : tout nouveau code = ARB fr+ar + `switch`.
- Decimaux en texte (`DecimalTextConverter`), dates metier `yyyy-MM-dd`, versions serveur en `int` comparees numeriquement.
- `LtrText` pour codes, dates, cotes, montants ; dans une phrase arabe : `Formatters.isolateLtr` (LRI/PDI). Boutons principaux 56 dp, texte >= 16 sp, valeurs cles 20 sp.
- Aucune ecriture locale sans operation d'envoi : `OutboxRepository.saveWithOperation` (une transaction). `clientId` cree a l'ouverture du formulaire.
- Tri des noms : `core/utils/collation.dart` (SQLite ne plie pas les accents).
- Demandes de materiaux (`features/materials/`, schema Drift v2) : tables `products suppliers material_requests deliveries delivery_photos pending_photo_files app_settings` ; statuts/urgences/unites gardes en TEXTE recu (enums `tryParse`, valeur inconnue affichee telle quelle) ; ligne locale en attente = `id == clientId`, `version 0`, `isPending`, `number null` ; `upsertIfNewer` remplace la ligne locale de meme `clientId` ET rattache livraisons/photos/fichiers/zone qui la designaient.
- **Aucun prix / telephone en base** : `MaterialJsonGuard` (liste blanche) applique par les DAO a `order_json`/`history_json` ; `test/database/materials_privacy_test.dart` inspecte toutes les colonnes (seule exception `sites.contract_amount`). Un nouveau champ commercial = SQLCipher + ADR d'abord.
- Calcul d'affichage : `features/materials/domain/quantity_mirror.dart` (+ `algeria_date`, `product_search`, `material_settings`) teste par `docs/api/vecteurs-materiaux.json` (`test/features/materials/domain/shared_vectors_test.dart`, chemin `../docs/api/`). Le mobile ne calcule jamais de montant ; la section `amounts` du fichier ne teste que `roundAwayFromZero`.
- Ecriture des demandes : `features/materials/data/materials_repository.dart` (`createRequest`, `editRequest`, `approve`/`reject`/`cancel`) = ligne locale + operation `request` dans UNE transaction ; payloads dans `domain/request_operations.dart` (`RequestPayloads`, `RequestEdit.diff` : `changes` + `base` obligatoire pour chaque champ modifie, sinon 400 serveur) ; affichage = `overlayRequest` (ligne du serveur + saisies en attente, statut « a confirmer ») ; liste = `filterRequests` (statut AFFICHE, sauf « A valider » = statut stocke). Produit non modifiable hors ligne (annuler/recreer).
- Les lignes `product`/`supplier`/`request` du pull sont lues a la main (`materials_sync_decoder.dart`), pas par les modeles generes (historique : `fromStatus` nul refuse par `History`).
- Libelles : `core/l10n/labels.dart` (statut, urgence, unite, categorie, motif) et `core/l10n/quantity_format.dart` (`formatQuantity` = nombre + unite).

- Reseau : `core/network/*`, client genere `core/api/generated/` (jamais a la main) + `core/api/api_clients.dart`. Sync : `core/sync/{sync_engine,sync_scheduler,sync_status_cubit,current_site,outbox_repository}.dart`, decodeur `features/sites/data/sync_decoder.dart`.

- Apres changement de table : incrementer `AppDatabase.currentSchemaVersion`, `dart run drift_dev schema dump lib/database/app_database.dart drift_schemas/` puis `schema generate drift_schemas/ test/generated_migrations/`.
- Tests Drift sous Windows : `winsqlite3.dll` systeme (rien a installer) ; Linux : libsqlite3-dev.
- Essai reel : `ASPNETCORE_ENVIRONMENT=Development Seed__Demo=true dotnet run --no-build --no-launch-profile --urls http://localhost:8195` dans `chantier-backend/WebApi/Chantier.WebApi` ; mot de passe demo = `Seed:DemoPassword` (lu par script, jamais affiche). Arreter ensuite le processus du port 8195.

## Pièges connus
- Contrat : `openapi.json` est complete par le backend EN COURS de lot (B5 a B8 : commandes, livraisons, photos, suivi) : relancer `swagger_parser` + `build_runner` + `dart format lib` des que `generated_client_contract_test` rougit (additif, aucun ecran). Le test accepte un mot reserve renomme (`new` -> `newValue`, `@JsonKey(name:)`).
- Noms en double : les modeles generes (`RequestStatus`, `Quantity`, `MeasureUnit`) entrent en collision avec le domaine : `import ... generated/export.dart' show X` dans les fichiers qui touchent aussi au domaine ; le moteur n'importe jamais `material_enums`.
- `FilledButton.icon` n'est pas de type exact `FilledButton` : `find.widgetWithText(FilledButton, ...)` ne le trouve pas (utiliser `find.ancestor` + `is FilledButton`).
- Tests de widgets avec Drift : terminer par `pumpWidget(SizedBox())` + `runAsync(delay 30 ms)` + `pump(50 ms)` (sinon « minuteur en attente ») ; `tester.runAsync` pour toute ecriture en base ; `flutter test` d'un gros fichier peut depasser 3 min en cas de `pumpAndSettle` bloque : tuer `flutter_tester.exe`.
- Heredoc bash + apostrophes/`${}` en Python : ecrire le script avec l'outil Write puis l'executer.
- Arrondi : `Rational.round()` (paquet decimal) arrondit loin de zero ; `Decimal.round(scale)` aussi. Ne jamais arrondir deux fois (scale+2 puis scale). `Decimal.signum` est deprecie : comparer a `Decimal.zero`.
- ARB : une valeur arabe sans lettre arabe (ex. `{from} = {to}`) fait echouer `arb_parity_test` ; aucune chaine ne doit contenir `null|sql|http|exception|stack` (test des messages d'erreur). Script de generation des ARB : json.dump en `ensure_ascii=False`, indent 2, `newline='
'`.
- `Formatters.thousandsSeparator` est une espace insecable fine : l'utiliser dans les tests au lieu d'une espace.
- Tests lisant un fichier partage : lever `StateError` (pas `expect`) hors d'un `test(...)`.
- Drift : une colonne nullable ajoutee reste optionnelle dans le constructeur de la data class (les tests existants ne changent pas) ; migration additive = `addColumn` + `createTable` + `createIndex(idx...)` (noms generes dans `app_database.g.dart`), test `migration_test.dart` (`schemaAt(1)` + `rawDatabase.execute`).
- Champ reserve (montant du marche) : `upsertIfNewer` ignore les versions egales ; un changement de `permissionsVersion` passe par `AppDatabase.startFullReload(clearRestrictedFields: true)` (efface le montant tout de suite + drapeau `full_reload` qui ecrase pendant le rechargement). Ne jamais appeler `resetCursor` seul pour un changement de permissions.
- Android : `allowBackup="false"` + `res/xml/{data_extraction_rules,backup_rules}.xml` ; garde-fou `test/android/manifest_test.dart`. Release signe avec la cle de debug : documente (README « Livraison »), ne pas diffuser.
- Noms de personnes dans une phrase : `Formatters.isolateName` (latin isole, arabe laisse). Texte de ligne qui peut passer a la ligne a 320 dp / police x2 : `Expanded` dans le `Row`.
- Fiche chantier : `ListView.builder` sur une liste aplatie de closures (R1-15).
- Apostrophes dans un titre de test genere par script Python : les retirer (sinon Dart ne parse plus).
- Flutter 3.35.7 : `bloc_test` borne `analyzer` < 8 : drift/drift_dev 2.28, freezed 3.0, json_serializable 6.9, json_annotation 4.9, `drift_flutter` < 0.2.7, swagger_parser 1.46.0 (`use_freezed3: true`), retrofit 4.4.2 + retrofit_generator 9.1.9.
- Les clients generes ont des chemins complets `/api/v1/...` : leur `baseUrl` = `AppConfig.serverRootUrl` (sans `/api/v1`). `dio` nu (`bareDio`) pour login/refresh.
- `app_database.dart` doit importer convertisseurs et `decimal` (utilises par le `.g.dart`). `insertOnConflictUpdate(row)` ignore les `null` : utiliser `row.toCompanion(false)`.
- Bidi : ecrire `⁦`/`⁩` en echappements (lint `text_direction_code_point_in_literal`) ; `findTextContaining` (pump_app) ignore les isolats.
- Tests de widgets avec un Bloc : le creer DANS le test (pas dans `setUp`), sinon `pump` n'avance pas ses evenements. `ListView` ne construit que le visible : agrandir `tester.view.physicalSize`.
- `SegmentedButton` ignore `minimumSize` (hauteur = police + padding vertical).
- Le moteur n'a pas de `GET /health` : `GET /auth/me` sert d'appel leger et recharge permissions + `permissionsVersion`.
- Heredocs bash avec apostrophes : preferer l'outil Write (script Python dans le dossier scratchpad puis `python -I script.py`) ; `dart format` reformate les tests : ancres de remplacement courtes, jamais des blocs multi-lignes. Licences Android non acceptees : `flutter build bundle --debug` seulement.

- gen-l10n : l'ordre des parametres suit l'ordre des `placeholders` du `@cle` (ordre de declaration), pas l'ordre alphabetique ; verifier la signature generee. `PhotoResponse.toJson()` rend l'objet enum (pas la chaine) : construire la ligne champ par champ.
- Tests de widgets avec fichiers/isolat : `tester.runAsync` pour toute E/S reelle (`PhotoFiles`, `Sha256.hexOfFile`), puis boucle d'attente (`waitFor`) ; un test qui echoue en laissant une boite de dialogue ouverte fait « did not complete » sur tous les suivants (tuer `flutter_tester.exe`). Une livraison complete declenche « Receptionner maintenant ? » : decliner ('Plus tard') dans les tests d'enregistrement.
- Snackbar : texte present deux fois sous `Navigator.push` (Scaffold du dessous) : `findsWidgets`.
- Un nouveau code d'erreur du catalogue (`ERREUR_TEMPORAIRE`) casse `error_messages_test` tant que l'ARB fr+ar et le `switch` ne sont pas ajoutes.

## Décisions (lien ADR)
- ADR 0006/0008/0009. Refresh echoue : seuls les jetons sont effaces (`SessionEvent` authRequired / accessRevoked / passwordChangeRequired) ; la file d'envoi n'est jamais videe, sauf abandon explicite.
- Reste hors socle : WorkManager, SQLCipher (avant donnees personnelles ; les photos de bons du dossier prive ne sont pas chiffrees, R2-16), `integration_test` sur emulateur.
- Lot demandes-materiaux (plan `docs/plans/demandes-materiaux-livraisons.md`, ADR 0011-0014) : M1 a M9 faits (livraisons M6/M7, photos M8, « A verifier » passe 2) ; reste M10 (Commander mobile, hors perimetre). Paquets autorises et seuls ajoutes : `image_picker` (camera, sans permission), `path_provider` (dossier prive par proprietaire), `url_launcher` (`tel:`, `<queries>` DIAL).
- Livraisons : `features/materials/{domain/delivery_*.dart,data/deliveries_repository.dart,presentation/deliveries/}` ; operations `delivery` (`create/update/transition cancel`) et `photo` (`create`) dans `domain/delivery_operations.dart` ; `DeliveryView`/`overlayDelivery`/`applyDeliveries` (statut de la demande provisoire « a confirmer ») ; une saisie = livraison + ses photos dans UNE transaction (`OutboxRepository.saveWithOperations`, cle anti-doublon = clientId de la 1re operation). N° de bon : `normalizeNoteNumber` (majuscules) cote payload ET ligne locale.
- Photos : `data/{photo_files,photo_capture,photo_remote,photo_upload_service}.dart`, `core/utils/sha256.dart` (Dart pur, isolat). Le fichier part APRES le push des metadonnees (jointure `pending_photo_files` x `delivery_photos.is_pending = false`), un a la fois, supprime apres confirmation ; refus definitifs (`PhotoFileErrors.permanent`) gardes et signales ; 409 `CONFLIT_VERSION` rejoue 2 fois puis reprise par le moteur (R2-04). `PhotoViewer` = octets en memoire seulement, vide a la deconnexion (`AuthRepositoryImpl.onLocalDataPurged`).
- Pull : cles etrangeres SUSPENDUES le temps d'une page (`PRAGMA foreign_keys = OFF` hors transaction), orphelins retires a la derniere page (`AppDatabase.deleteOrphans`), cascade chantier explicite (`deleteSiteCascade`). Resultat de push `retry` (`ERREUR_TEMPORAIRE`) : operation gardee, JAMAIS renvoyee dans la meme execution (sinon boucle), execution finie en `failed` avec delai exponentiel.
- `retry` (R3-01) : le moteur ecarte les operations qui visent le `clientId` d'une operation a renvoyer (`requestClientId`/`deliveryClientId`/`zoneClientId`, transitif) ; une reponse `rejected`/`conflict` pour un dependant du meme lot est traitee comme `retry` (reste `pending`). Une correction d'une demande JAMAIS envoyee modifie le `create` (pas d'operation `update`).
- Rechargement (R3-05) : `SyncPullResponse.resetRequired` -> `AppDatabase.startWindowReload()` (efface demandes/livraisons/photos NON pending, `resetCursor`, drapeau `full_reload` = signal ignore jusqu'a la fin) ; aussi si `last_success_at` > `AppConfig.fullReloadAfterDays` (60, `FULL_RELOAD_AFTER_DAYS`). `deleteOrphans` ne retire jamais une ligne `is_pending`. `history[]` du pull est VIDE cote serveur (R2-02) : le detail lit l'historique a la demande (`HistorySource`/`HistoryRemoteSource`, corps brut `GET /sites/{s}/requests|deliveries/{id}`, assaini par `MaterialJsonGuard`, copie en memoire seulement videe a la deconnexion) via `HistorySection` ; hors ligne : « Historique indisponible hors ligne ». Pas de purge locale periodique (decision coordinateur : le rechargement complet suffit).
- Ecrans de liste : l'en-tete (recherche + `Wrap` de pastilles) est le premier element du `ListView.builder` (D-3), jamais une `Column` fixe au-dessus.
- Listes (R2-07) : `watchBySiteLight` (sans `history_json`, `order_json` conserve : petit) + `throttleLatest` 300 ms (nul en test). `OrderInfo` (`order_json` -> fournisseur, date prevue).
